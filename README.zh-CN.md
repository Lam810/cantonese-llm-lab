# Cantonese-LLM-Lab — 粤语大模型微调、评测与昇腾国产卡适配

[粵語](README.md) · **简体中文** · [English](README.en.md)

本项目涵盖粤语大模型的**微调、评测与昇腾适配**，并提供可复用的脚本。

本项目包括以下六部分：
1. **一套不依赖 LLM 评审的评测** —— HKMMLU 官方口径全量、官方粤↔普翻译任务、
   书面粤语纯度、退化检测、困惑度，全部逐题配对做 McNemar 精确检验；
2. **提示词消融方法** —— 2×2（语言 × 格式脚手架），用于检验排名是否由提示词选择造成；
3. **一个发布闸门** —— 非劣效检验（而非显著性检验）＋ δ 敏感性检查；
4. **一个 LoRA 诊断工具** —— 逐模块 ‖ΔW‖/‖W‖；
5. **一份多源粤语 SFT 数据重建脚本** —— 含简繁归一、两级去重、先切分后训练；
6. **昇腾 910C 适配记录** —— 从 CUDA 搬过去只改 4 行，加上原生 W8A8 量化、
   图模式优化的**负结果**，以及若干错误信息与实际原因不匹配的问题。

## 最新结果（2026-09-18）

本项目有**两条并列的模型线**，不设旗舰——它们的强项不同：

| | HKMMLU（知识） | 普→粤（产出粤语） | 粤→普（理解粤语） | 解析失败 |
|---|---|---|---|---|
| **30B-A3B（MoE，仅注意力 LoRA）** | **0.6467（第 1 / 11）** | 44.51 | **57.30** | **0.0003** |
| **8B（dense，七模块 LoRA）** | 0.5394（第 6 / 11） | **52.36** | 52.81 | 0.0442 |

**知识问答与格式遵从用 30B；生成地道书面粤语仍用 8B。**
30B 那一轮的完整结果、增益归因（换基座 vs 换配方、扣除格式分量）与已知取舍见
[`results/moe_30b.md`](results/moe_30b.md)。

下面〈一〉〈二〉两节是 **8B 量级 8 个模型**的对照，口径与 30B 那轮完全相同。

**一、HKMMLU 官方口径，全量 26,368 题：8B 版本第 4 / 8。**

| 排名 | 模型 | 准确率 | 95%CI | 解析失败 | 平均输出tok |
|---|---|---|---|---|---|
| 1 | `CantoneseLLMChat-v1.0-7B` | 0.5897 | ±0.59pp | 0.0000 | 11.7 |
| 2 | `Qwen2-Cantonese-7B-Instruct` | 0.5883 | ±0.59pp | 0.0000 | 8.8 |
| 3 | **本项目 消融版（仅公开数据）** | 0.5560 | ±0.60pp | 0.0000 | 9.1 |
| 4 | **本项目 v2** | 0.5394 | ±0.60pp | **0.0442** | 13.0 |
| 5 | `Llama-3-Cantonese-8B-Instruct` | 0.5240 | ±0.60pp | 0.0005 | 4.4 |
| 6 | `Qwen3-8B`（基座） | 0.4697 | ±0.60pp | 0.0281 | 471 |
| 7 | `CantoneseLLM-v2.0-8B-Thinking` | 0.3993 | ±0.59pp | 0.0825 | 451 |
| 8 | `v2.0-8B-Thinking-Chat-Vector-Merged` | 0.3968 | ±0.59pp | 0.0736 | 493 |

配对 McNemar：8B 版本落后本表第一名 **−5.03pp**（95%CI [−5.68,−4.37]，p=1.6e-51），
差异具有统计显著性。

> 本表不含 30B 那一轮。同口径下：本项目 30B-A3B **0.6467**（超过本表第一名 **+5.69pp**，
> 95%CI [+5.07,+6.38]，p=2.5e-63）、`Qwen/Qwen3-30B-A3B`（基座）0.4487。
> 放进本表，本项目 30B 排第 1、其基座排第 10。

**该排名在提示词消融中保持稳定。** 提示词做了个 2×2（语言 × 格式脚手架）＋两种题量
= **8 种组合，对手全部赢我们**；就算允许每个模型各取自己最好的那一臂，
也是 `chat_7b` 0.6018 > `qwen2` 0.5889 > 本项目 0.5767。
详见 [`results/prompt_ablation.md`](results/prompt_ablation.md)。

**二、官方翻译任务：两个方向名次完全反过来。该结果反映两个方向的能力差异。**

| | 粤→普 chrF | 普→粤 chrF |
|---|---|---|
| **本项目 v2** | 23.95（剥离繁简后 **52.81**） | **51.57**（第 1） |
| `CantoneseLLMChat-v1.0-7B` | **59.51**（60.09） | 46.06 |
| `Llama-3-Cantonese-8B-Instruct` | 16.74（31.94） | 48.18 |
| `Qwen2-Cantonese-7B-Instruct` | 13.94（26.27） | 37.94 |

**产出粤语我们第 1**（51.57 对 46.06）。**理解粤语**原始数字第 4，但官方参考译文是
**简体**、我们输出**繁体**，而 chrF 是字符级的——剥离字形之后是**第 3、差 7.28 点**，
不是原先说的 35.6 点。实测有句子语域全转对（喺→在 同→和 係→是 嘅→的）只差字形却拿接近 0 分。

**三、主要限制是指令服从，而不是知识或粤语理解。**

| 证据 | 数字 |
|---|---|
| HKMMLU 解析失败率 | **4.42%**（两个强对手都是 0.0000） |
| 加一句格式脚手架后，涨的分里有多少只是「终于能被解析出来」 | **32%**，8 个模型里最高（基座 4%、Thinking 12%） |
| 粤→普 任务的繁体输出率 | **99.7%**（提示词明写「简体中文」；对手 5.0%） |

三条证据来源互相独立、方向一致。**相应干预也定位了主要限制**：
加脚手架解析失败率从 4.42% 降到 0.62%（降 86%），换粤语提示词只到 4.01%（几乎不动）。
**后续训练应增加格式服从类数据，而不是单纯增加粤语语料。**

另外两项确实输：`hk_*`（香港本地知识）0.5334 倒数第二（对手 0.6243）；
粤语维基困惑度 13.45 对 `CantoneseLLMChat-v1.0-7B` 的 7.77——他们做继续预训练（CPT），
我们只做 LoRA SFT。两者的训练目标不同：**对方是粤语语言模型，本项目是具备粤语生成能力的问答模型**；
两个翻译方向的结果也与此差异一致。
详见 [`results/standard_eval.md`](results/standard_eval.md)。

**四、非思维链部署的结果较为稳定。**
平均输出 **13 tok**，基座 471、两个 Thinking 版 451／493——**35 倍上下**。
在不能用思维链的场景（短回答、低延迟、按 token 计费、边缘设备）它们没法用。

**五、公开数据子集在两种评测口径下均优于完整语料。**
授权原因，71,202 条里只有 27,207 条可再分发。尽管公开子集规模较小，
**实测结果反而更高**：logprob 口径 **+1.19pp**（p=6.0e-7）、官方口径 **+1.65pp**（p=5.8e-10）。
在另一评测口径下重新测量后，差距进一步扩大，并非单一口径造成。
两个版本的权重均已发布，该消融可根据公开权重和评测脚本复现。
详见 [`results/ablation_clean_data.md`](results/ablation_clean_data.md)。

**六、昇腾原生 W8A8_DYNAMIC 已发布**
msmodelslim 做的动态 W8A8（11.1 GiB），`vllm-ascend` 直接加载。全量 26,368 题、
同口径 bf16 对照、逐题配对：Δ **−0.46pp**，95%CI [−0.93,+0.00]，
损失置信上界 0.93pp ≤ 容差 δ=2.0pp。**静态 W8A8 版本未予发布**：
其吞吐量高 64%，但输出出现严重退化，原因是未生成 EOS 标记并持续生成至上限。
详见 [`results/quantization.md`](results/quantization.md)。

## 评测任务说明



| 任务 | 做法 | 为什么这样做 |
|---|---|---|
| **HKMMLU（主口径）** | **官方 zero-shot prompting**：要模型直接输出字母，贪心解码，全量 26,368 题 | 官方标准就是 prompting（见数据集 README），**这个口径才与官方榜单可比**。解析不出来的**单独记 `unparsed_rate`、按答错计，不静默丢弃** |
| HKMMLU（辅助口径） | 比较 `A/B/C/D` 四个字母 token 的 logprob | 绕开「指令遵循能力」这个混淆变量，量纯知识。**但与官方榜单不可直接比**，只做辅助 |
| **官方翻译任务** | 粤→普／普→粤 各 2,000 条，chrF ＋ BLEU(zh)，**同时报繁简归一后的分** | 选择题无法测量模型生成粤语的能力，因此另设该任务。**两个方向应分开解读**，因为产出与理解是两种能力 |
| **书面粤语纯度** | 粤语虚词（嘅係唔咗喺佢哋…）与普通话虚词（的是不了在他们…）的计数比 | 直接测量模型输出偏向粤语或普通话；**应与退化率结合解读**，避免单一词语在退化输出中造成误判 |
| **退化检测** | 贪心解码下 `(.{6,})\1{2,}` 命中率 | 用于检测输出是否出现重复或其他语言退化 |
| **困惑度** | 同时报 PPL 和 **bits-per-char** | 不同模型分词器不同，PPL 不可直接比，bits-per-char 可以 |

## 数据重建

合并四个公开来源（作者自建的粤语指令集、粤语 CoT、粤语对话、粤中平行语料），
统一 opencc `s2hk` 字形，两级去重（整条 + 同 instruction），按来源分层切分，
固定 `seed=42`：**71,202 条**（train 68,202 / dev 1,000 / test 2,000）。
确定性已验证：两台不同机器重跑，各来源条数、去重数、切分大小逐项一致。

⚠️ **合并语料不再分发**——四个来源里有一个**没有任何授权声明**、一个是 **AGPL-3.0**，
占了 62%。公开的是脚本；可再分发的那 27,207 条（自有 + CC0）单独发在
[`Zeteng/cantonese-llm-data`](https://huggingface.co/datasets/Zeteng/cantonese-llm-data) 的
`v2-clean/`。详见 [`docs/data-licensing.md`](docs/data-licensing.md)。

以下两项统计值得注意：
- **50,606 条**记录在建库时被简繁归一化过——公开粤语语料的简繁混排问题是大面积的；
- 粤语纯度中位数 1.0、均值 0.824。**纯度只度量不过滤**：清洗阈值最容易把最该研究的样本丢掉，
  要做消融再用 `--min-yue-ratio`。
