# Cantonese-LLM-Lab — 粤语大模型微调、评测与昇腾国产卡适配

[粵語](README.md) · **简体中文** · [English](README.en.md)

粤语大模型的**微调、评测与昇腾适配**工程笔记，附可直接复用的脚本。

这里包括六件东西：
1. **一套不依赖 LLM 判官的评测** —— HKMMLU 官方口径全量、官方粤↔普翻译任务、
   书面粤语纯度、退化检测、困惑度，全部逐题配对做 McNemar 精确检验；
2. **提示词消融的做法** —— 2×2（语言 × 格式脚手架），量清「排名是不是提示词选出来的」；
3. **一个发布闸门** —— 非劣效检验（不是显著性检验）＋ δ 敏感性自检；
4. **一个 LoRA 体检工具** —— 逐模组 ‖ΔW‖/‖W‖；
5. **一份多源粤语 SFT 数据重建脚本** —— 含简繁归一、两级去重、先切分后训练；
6. **昇腾 910C 适配记录** —— 从 CUDA 搬过去只改 4 行，加上原生 W8A8 量化、
   图模式优化的**负结果**，以及一堆「报错指不到真因」的坑。

## 最新结果（2026-09-17）

**一、HKMMLU 官方口径，全量 26,368 题：我们第 4 / 8。**

| 排名 | 模型 | 准确率 | 95%CI | 解析失败 | 平均输出tok |
|---|---|---|---|---|---|
| 1 | `CantoneseLLMChat-v1.0-7B` | 0.5897 | ±0.59pp | 0.0000 | 11.7 |
| 2 | `Qwen2-Cantonese-7B-Instruct` | 0.5883 | ±0.59pp | 0.0000 | 8.8 |
| 3 | **本项目 消融版（仅公开数据）** | 0.5560 | ±0.60pp | 0.0000 | 9.1 |
| 4 | **本项目 v2** | 0.5394 | ±0.60pp | **0.0442** | 13.0 |
| 5 | `Llama-3-Cantonese-8B-Instruct` | 0.5240 | ±0.60pp | 0.0005 | 4.4 |
| 6 | `Qwen3-8B`（基座） | 0.4697 | ±0.60pp | 0.0281 | 471 |
| 7 | `CantoneseLLM-v2.0-8B-Thinking` | 0.3993 | ±0.59pp | 0.0825 | 451 |
| 8 | `v2.0-8B-Thinking-Chat-Vector-Merged` | 0.3968 | ±0.59pp | 0.0736 | 493 |

配对 McNemar：落后第一名 **−5.03pp**（95%CI [−5.68,−4.37]，p=1.6e-51），**不是噪声**。

**而且这个名次是稳的。** 提示词做了个 2×2（语言 × 格式脚手架）＋两种题量
= **8 种组合，对手全部赢我们**；就算允许每个模型各取自己最好的那一臂，
也是 `chat_7b` 0.6018 > `qwen2` 0.5889 > 本项目 0.5767。
详见 [`results/prompt_ablation.md`](results/prompt_ablation.md)。

**二、官方翻译任务：两个方向名次完全反过来。这组数字信息量最大。**

| | 粤→普 chrF | 普→粤 chrF |
|---|---|---|
| **本项目 v2** | 23.95（剥离繁简后 **52.81**） | **51.57**（第 1） |
| `CantoneseLLMChat-v1.0-7B` | **59.51**（60.09） | 46.06 |
| `Llama-3-Cantonese-8B-Instruct` | 16.74（31.94） | 48.18 |
| `Qwen2-Cantonese-7B-Instruct` | 13.94（26.27） | 37.94 |

**产出粤语我们第 1**（51.57 对 46.06）。**理解粤语**原始数字第 4，但官方参考译文是
**简体**、我们输出**繁体**，而 chrF 是字符级的——剥离字形之后是**第 3、差 7.28 点**，
不是原先说的 35.6 点。实测有句子语域全转对（喺→在 同→和 係→是 嘅→的）只差字形却拿接近 0 分。

**三、我们真正的短板：指令服从，不是知识、不是粤语理解。**

| 证据 | 数字 |
|---|---|
| HKMMLU 解析失败率 | **4.42%**（两个强对手都是 0.0000） |
| 加一句格式脚手架后，涨的分里有多少只是「终于能被解析出来」 | **32%**，8 个模型里最高（基座 4%、Thinking 12%） |
| 粤→普 任务的繁体输出率 | **99.7%**（提示词明写「简体中文」；对手 5.0%） |

三条证据来源互相独立、方向一致。而且**短板的位置被「能修它的那个干预」指了出来**：
加脚手架解析失败率从 4.42% 降到 0.62%（降 86%），换粤语提示词只到 4.01%（几乎不动）。
**下一轮配方该补的是格式服从类数据，不是更多粤语语料。**

另外两项确实输：`hk_*`（香港本地知识）0.5334 倒数第二（对手 0.6243）；
粤语维基困惑度 13.45 对 `CantoneseLLMChat-v1.0-7B` 的 7.77——他们做继续预训练（CPT），
我们只做 LoRA SFT。诚实讲：**他们的是「粤语语言模型」，我们的是「会说粤语的问答模型」**，
翻译任务那两个方向刚好把这句话量化了。
详见 [`results/standard_eval.md`](results/standard_eval.md)。

**四、站得住的一条：非思维链部署。**
平均输出 **13 tok**，基座 471、两个 Thinking 版 451／493——**35 倍上下**。
在不能用思维链的场景（短回答、低延迟、按 token 计费、边缘设备）它们没法用。

**五、公开出去的数据子集，比完整语料训得更好，两个口径都是。**
授权原因，71,202 条里只有 27,207 条可再分发。原本以为公开那份是「阉割版」——
**实测是相反**：logprob 口径 **+1.19pp**（p=6.0e-7）、官方口径 **+1.65pp**（p=5.8e-10）。
**换了尺子重测一次，差距还更大了**，所以不是某一种口径的产物。
两个版本的权重都已发布，**这个消融你可以自己验证**。
详见 [`results/ablation_clean_data.md`](results/ablation_clean_data.md)。

**六、昇腾原生 W8A8_DYNAMIC 已发布，过非劣效闸门。**
msmodelslim 做的动态 W8A8（11.1 GiB），`vllm-ascend` 直接加载。全量 26,368 题、
同口径 bf16 对照、逐题配对：Δ **−0.46pp**，95%CI [−0.93,+0.00]，
损失置信上界 0.93pp ≤ 容差 δ=2.0pp。**静态 W8A8 那版我们试过，不发**：
它吞吐还高 64%，但输出是 token 沙拉——**因为它从不吐 EOS、一路生成到上限**。
详见 [`results/quantization.md`](results/quantization.md)。

## 主要结论

**1. 没有验证集的 SFT，训练 loss 曲线不能证明任何事。**
出事的那次训练，loss 在 200 步内从 1.59 掉到 0.25 然后 6400 步走平——看起来像收敛，
实际是塌进了输出重复串的退化解。`eval_strategy="no"` 让这两种情况在日志上长得一模一样。

**2. 权重差 ‖ΔW‖/‖W‖ 是最快的 LoRA 体检。**
310 个张量里 254 个完全没动（和 `target_modules` 吻合），但最后 5 层的 `q_proj`
相对差达到 **0.50 ~ 1.06**——r=8/alpha=16 的 LoRA 正常应在 0.01–0.05。
发散是结构化的：只打在最靠近输出的几层 query 投影上。

**3. 把未合并的 adapter 挂回原始基座，能一步分开「训练坏了」和「合并坏了」。**
两者都退化 ⇒ 合并不是根因。

**4. 一套 CUDA 评测脚本搬到昇腾，代码只需改 4 行；准确率对得上（3300 题差 6 题），吞吐差 3.6 倍。**
`vllm-ascend` 起 OpenAI 兼容服务也是通的（0.6B / TP=1，**65 秒就绪**），
但有两个报错指不到真因的坑：缺 **NNAL/ATB**（`libatb.so`，不在 CANN 里、要单独 source），
以及 **`set -u` 会让脚本在 source 昇腾环境时静默退出**。

**5. 跨简繁的字符串指标必须两种字形都写。**
只写简体的「普通话标记词」在繁体语料上整张表静默失配，把粤语纯度虚高成 0.964（真值 0.824）。

**6. 对带思维链的模型做「第一个 token」类打分，先确认第一个 token 是不是答案位。**
选择题比较 A/B/C/D 的 logprob，而 Qwen3 默认开思维链、第一个 token 是 `<think>`，
量到的是「它想先想一想」。基座因此只有 0.2888（近随机），关掉后是 0.5700。
详见 [`results/v2_results.md`](results/v2_results.md)。

**7.「本地重新合并的权重」和「实际被评测的权重」只是假定等价——要验。**
搬 16GB 不现实时，只搬 349MB 的 adapter、本地合并是对的；但必须用带鉴权的 HTTP range
请求逐字节比对（抽 3 个张量各 32,768 个 bf16 元素，100% 相同）。
同一个代理可能下载 8.7 MB/s、上传 50 KB/s——**两个方向要分别测**，
而且**估工期要用「已传字节 ÷ 已耗时」，不能用秒级瞬时速率**。
HF 的 Xet 后端对大文件会报 `xorb not found` 整批失败，`HF_HUB_DISABLE_XET=1` 可绕过。
详见 [`docs/publishing-logistics.md`](docs/publishing-logistics.md)。

**8. 为「让解析跑通」而加进提示词的那句话，会变成实验变量。**
为了让正则解析得出答案，在提示词末尾加了「請喺最後一行寫「答案：X」」。
动机纯工程性，但它同时改变了模型的行为空间（允许先写推理再作答），
于是变成一个**没有声明的实验变量**。全量配对实测：基座 +5.51pp、Thinking +3.98pp、
本项目 +3.00pp，而三个本来就 0 解析失败的对手是 **−0.14 ~ −0.93pp**。
**判断一个口径能不能用，要看它对所有被比较对象是否同等中立，不是看它听起来公平。**
真正该报的是**排名对提示词稳不稳**。
详见 [`results/prompt_ablation.md`](results/prompt_ablation.md)。

**9. 显著性不能当容差门槛——n 越大越容易显著。**
同一个量化变体，3300 题测出 −1.48pp（p=0.025，显著），全量 26,368 题测出
−0.46pp（p=0.052，不显著）。如果规则是「不显著才发」，**数据越多越发不出去**，荒谬。
容差判断的正确形式是**非劣效检验**：先定可接受损失上限 δ，再要求**损失的 95%
置信上界 ≤ δ**。同时记住两个模型答的是同一批题，**必须配对**——用两个比例各自的
标准误会高估方差（0.87pp 对配对后 0.65pp），把真实退化说成噪声。
**而且要检查判定对 δ 敏不敏感，不是把 δ 论证得多完美**（`eval/gate_check.py` 会打印）。

**10. 在 N 行的表上看 M<N 行就下「只有 X 才如何」这种全称结论，会翻车。**
补齐 8 个模型后，结果显示基座和 Thinking 版受益都比我们大。缺的那 3 行正好是行为最极端的三个
（两个思维链模型 + 基座），而它们才最需要格式提示。

**11. 字符级指标（chrF/BLEU）在跨简繁的任务上，必须同时报归一后的分。**
官方粤→普 参考译文是简体、我们输出繁体，chrF 是字符级的，于是语域已经全转对
（喺→在 同→和 係→是 嘅→的）的句子拿接近 0 分。原始 23.95、归一后 **52.81**，
差 **28.86 点**。两个都要报：原始量「有没有照做指令」，归一量「有没有转换语域」，
**两者的差就是字形合规值多少分**。归一用纯字形的 `zh-hans`，不用会换词汇的 `zh-cn`。

详见 [`docs/v1-postmortem.md`](docs/v1-postmortem.md) 和 [`docs/ascend-notes.md`](docs/ascend-notes.md)。

## 评测任务说明

三个任务**都不依赖 LLM 判官**，可复算：

| 任务 | 做法 | 为什么这样做 |
|---|---|---|
| **HKMMLU（主口径）** | **官方 zero-shot prompting**：要模型直接输出字母，贪心解码，全量 26,368 题 | 官方标准就是 prompting（见数据集 README），**这个口径才与官方榜单可比**。解析不出来的**单独记 `unparsed_rate`、按答错计，不静默丢弃** |
| HKMMLU（辅助口径） | 比较 `A/B/C/D` 四个字母 token 的 logprob | 绕开「指令遵循能力」这个混淆变量，量纯知识。**但与官方榜单不可直接比**，只做辅助 |
| **官方翻译任务** | 粤→普／普→粤 各 2,000 条，chrF ＋ BLEU(zh)，**同时报繁简归一后的分** | 选择题量不到「能不能产出粤语」，这个量得到。**两个方向要分开看**——产出与理解是两种能力 |
| **书面粤语纯度** | 粤语虚词（嘅係唔咗喺佢哋…）与普通话虚词（的是不了在他们…）的计数比 | 直接量「它到底在说粤语还是普通话」；**必须和退化率一起看**，否则一串乱码里出现一个「嘅」也会是 1.0 |
| **退化检测** | 贪心解码下 `(.{6,})\1{2,}` 命中率 | 一票否决项：模型还会不会说人话 |
| **困惑度** | 同时报 PPL 和 **bits-per-char** | 不同模型分词器不同，PPL 不可直接比，bits-per-char 可以 |

## 数据重建

合并四个公开来源（作者自建的粤语指令集、粤语 CoT、粤语对话、粤中平行语料），
统一 opencc `s2hk` 字形，两级去重（整条 + 同 instruction），按来源分层切分，
固定 `seed=42`：**71,202 条**（train 68,202 / dev 1,000 / test 2,000）。
确定性已验证：两台不同机器重跑，各来源条数、去重数、切分大小逐项一致。

⚠️ **合并语料不再分发**——四个来源里有一个**没有任何授权声明**、一个是 **AGPL-3.0**，
占了 62%。公开的是脚本；可再分发的那 27,207 条（自有 + CC0）单独发在
[`Zeteng/cantonese-llm-data`](https://huggingface.co/datasets/Zeteng/cantonese-llm-data) 的
`v2-clean/`。详见 [`docs/data-licensing.md`](docs/data-licensing.md)。

两个值得记下的数字：
- **50,606 条**记录在建库时被简繁归一化过——公开粤语语料的简繁混排问题是大面积的；
- 粤语纯度中位数 1.0、均值 0.824。**纯度只度量不过滤**：清洗阈值最容易把最该研究的样本丢掉，
  要做消融再用 `--min-yue-ratio`。
