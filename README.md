# Cantonese-LLM-Lab — 粵語大模型微調、評測同昇騰國產卡適配

**粵語** · [简体中文](README.zh-CN.md) · [English](README.en.md)

本項目涵蓋粵語大模型嘅**微調、評測同昇騰適配**，並提供可複用嘅腳本。

本項目包括以下六部分：
1. **一套不依賴 LLM 評審嘅評測** —— HKMMLU 官方口徑全量、官方粵↔普翻譯任務、
   書面粵語純度、退化檢測、困惑度，全部逐題配對做 McNemar 精確檢驗；
2. **提示詞消融方法** —— 2×2（語言 × 格式腳手架），用於檢驗排名是否由提示詞選擇造成；
3. **一個發佈閘門** —— 非劣效檢驗（而非顯著性檢驗）＋ δ 敏感性檢查；
4. **一個 LoRA 診斷工具** —— 逐模組 ‖ΔW‖/‖W‖；
5. **一份多源粵語 SFT 數據重建腳本** —— 含簡繁歸一、兩級去重、先切分後訓練；
6. **昇騰 910C 適配記錄** —— 由 CUDA 搬過去只改 4 行，加上原生 W8A8 量化、
   圖模式優化嘅**負結果**，以及若干錯誤訊息與實際根因不匹配嘅問題。

## 最新結果（2026-09-18）

本項目有**兩條並列嘅模型線**，不設旗艦——佢哋嘅強項唔同：

| | HKMMLU（知識） | 普→粵（產出粵語） | 粵→普（理解粵語） | 解析失敗 |
|---|---|---|---|---|
| **30B-A3B（MoE，只有注意力 LoRA）** | **0.6467（第 1 / 11）** | 44.51 | **57.30** | **0.0003** |
| **8B（dense，七模組 LoRA）** | 0.5394（第 6 / 11） | **52.36** | 52.81 | 0.0442 |

**知識問答同格式遵從用 30B；生成地道書面粵語仍然用 8B。**
30B 嗰一輪嘅完整結果、增益歸因（換基座 vs 換配方、扣除格式分量）同已知取捨見
[`results/moe_30b.md`](results/moe_30b.md)。

下面〈一〉〈二〉兩節係 **8B 量級 8 個模型**嘅對照，口徑同 30B 嗰輪完全相同。

**一、HKMMLU 官方口徑，全量 26,368 題：8B 版本第 4 / 8。**

| 排名 | 模型 | 準確率 | 95%CI | 解析失敗 | 平均輸出tok |
|---|---|---|---|---|---|
| 1 | `CantoneseLLMChat-v1.0-7B` | 0.5897 | ±0.59pp | 0.0000 | 11.7 |
| 2 | `Qwen2-Cantonese-7B-Instruct` | 0.5883 | ±0.59pp | 0.0000 | 8.8 |
| 3 | **本項目 消融版（只用公開數據）** | 0.5560 | ±0.60pp | 0.0000 | 9.1 |
| 4 | **本項目 v2** | 0.5394 | ±0.60pp | **0.0442** | 13.0 |
| 5 | `Llama-3-Cantonese-8B-Instruct` | 0.5240 | ±0.60pp | 0.0005 | 4.4 |
| 6 | `Qwen3-8B`（基座） | 0.4697 | ±0.60pp | 0.0281 | 471 |
| 7 | `CantoneseLLM-v2.0-8B-Thinking` | 0.3993 | ±0.59pp | 0.0825 | 451 |
| 8 | `v2.0-8B-Thinking-Chat-Vector-Merged` | 0.3968 | ±0.59pp | 0.0736 | 493 |

配對 McNemar：8B 版本落後本表第一名 **−5.03pp**（95%CI [−5.68,−4.37]，p=1.6e-51），
差異具有統計顯著性。

> 本表不含 30B 嗰一輪。同口徑之下：本項目 30B-A3B **0.6467**（超過本表第一名 **+5.69pp**，
> 95%CI [+5.07,+6.38]，p=2.5e-63）、`Qwen/Qwen3-30B-A3B`（基座）0.4487。
> 放入本表，本項目 30B 排第 1、其基座排第 10。

**該排名在提示詞消融中保持穩定。** 提示詞做咗個 2×2（語言 × 格式腳手架）＋兩種題量
= **8 種組合，對手全部贏我哋**；就算容許每個模型各取自己最好嗰一臂，
都係 `chat_7b` 0.6018 > `qwen2` 0.5889 > 本項目 0.5767。
詳見 [`results/prompt_ablation.md`](results/prompt_ablation.md)。

**二、官方翻譯任務：兩個方向名次完全反過來。該結果反映兩個方向嘅能力差異。**

| | 粵→普 chrF | 普→粵 chrF |
|---|---|---|
| **本項目 v2** | 23.95（剝走繁簡後 **52.81**） | **51.57**（第 1） |
| `CantoneseLLMChat-v1.0-7B` | **59.51**（60.09） | 46.06 |
| `Llama-3-Cantonese-8B-Instruct` | 16.74（31.94） | 48.18 |
| `Qwen2-Cantonese-7B-Instruct` | 13.94（26.27） | 37.94 |

**產出粵語我哋第 1**（51.57 對 46.06）。**理解粵語**原始數字第 4，但官方參考譯文係
**簡體**、我哋輸出**繁體**，而 chrF 係字符級嘅——剝走字形之後係**第 3、差 7.28 點**，
唔係原先講嘅 35.6 點。實測有句子語域全轉對（喺→在 同→和 係→是 嘅→的）只差字形卻拿接近 0 分。

**三、主要限制係指令服從，而唔係知識或粵語理解。**

| 證據 | 數字 |
|---|---|
| HKMMLU 解析失敗率 | **4.42%**（兩個強對手都係 0.0000） |
| 加一句格式腳手架後，漲嘅分裡有幾多只係「終於解析得出嚟」 | **32%**，8 個模型裡最高（基座 4%、Thinking 12%） |
| 粵→普 任務嘅繁體輸出率 | **99.7%**（提示詞明寫「簡體中文」；對手 5.0%） |

三條證據來源互相獨立、方向一致。**相應干預亦定位咗主要限制**：
加腳手架解析失敗率由 4.42% 跌到 0.62%（降 86%），換粵語提示詞只到 4.01%（幾乎冇動）。
**後續訓練應增加格式服從類數據，而唔係單純增加粵語語料。**

另外兩項確實輸：`hk_*`（香港本地知識）0.5334 倒數第二（對手 0.6243）；
粵語維基困惑度 13.45 對 `CantoneseLLMChat-v1.0-7B` 嘅 7.77——他們做繼續預訓練（CPT），
我哋只做 LoRA SFT。兩者嘅訓練目標唔同：**對方係粵語語言模型，本項目係具備粵語生成能力嘅問答模型**；
兩個翻譯方向嘅結果亦與此差異一致。
詳見 [`results/standard_eval.md`](results/standard_eval.md)。

**四、非思維鏈部署嘅結果較為穩定。**
平均輸出 **13 tok**，基座 471、兩個 Thinking 版 451／493——**35 倍上下**。
喺唔可以用思維鏈嘅場景（短回答、低延遲、按 token 計費、邊緣設備）它們冇法用。

**五、公開數據子集在兩種評測口徑下均優於完整語料。**
授權原因，71,202 條裡面只有 27,207 條可以再分發。雖然公開子集嘅規模較小，
**實測結果反而較高**：logprob 口徑 **+1.19pp**（p=6.0e-7）、官方口徑 **+1.65pp**（p=5.8e-10）。
以另一評測口徑重新測量後，差距進一步擴大，並非單一口徑造成。
兩個版本嘅權重均已發佈，該消融可根據公開權重同評測腳本復現。
詳見 [`results/ablation_clean_data.md`](results/ablation_clean_data.md)。

**六、昇騰原生 W8A8_DYNAMIC 已發佈**
msmodelslim 造嘅動態 W8A8（11.1 GiB），`vllm-ascend` 直接載。全量 26,368 題、
同口徑 bf16 對照、逐題配對：Δ **−0.46pp**，95%CI [−0.93,+0.00]，
損失置信上界 0.93pp ≤ 容差 δ=2.0pp。**靜態 W8A8 版本未予發佈**：
其吞吐量高 64%，但輸出出現嚴重退化，原因係未生成 EOS 標記並持續生成至上限。
詳見 [`results/quantization.md`](results/quantization.md)。

## 評測任務講解

| 任務 | 做法 | 點解要咁做 |
|---|---|---|
| **HKMMLU（主口徑）** | **官方 zero-shot prompting**：要模型直接輸出字母，貪心解碼，全量 26,368 題 | 官方標準就係 prompting（見數據集 README），**呢個口徑才同官方榜單可比**。解析唔出嚟嘅**單獨記 `unparsed_rate`、按答錯計，唔靜默丟棄** |
| HKMMLU（輔助口徑） | 比較 `A/B/C/D` 四個字母 token 嘅 logprob | 繞開「指令遵循能力」呢個混淆變量，量純知識。**但同官方榜單唔可以直接比**，只做輔助 |
| **官方翻譯任務** | 粵→普／普→粵 各 2,000 條，chrF ＋ BLEU(zh)，**同時報繁簡歸一後嘅分** | 選擇題無法測量模型生成粵語嘅能力，因此另設該任務。**兩個方向應分開解讀**，因為產出同理解係兩種能力 |
| **書面粵語純度** | 粵語虛詞（嘅係唔咗喺佢哋…）同普通話虛詞（的是不了在他們…）嘅計數比 | 直接測量模型輸出偏向粵語或普通話；**應與退化率結合解讀**，避免單一詞語喺退化輸出中造成誤判 |
| **退化檢測** | 貪心解碼下 `(.{6,})\1{2,}` 嘅命中率 | 用於檢測輸出是否出現重複或其他語言退化 |
| **困惑度** | 同時報 PPL 同 **bits-per-char** | 唔同模型分詞器唔同，PPL 直接比唔得，bits-per-char 就比得 |

**兩個都係逐題配對做 McNemar 精確檢驗**（唔用兩個獨立比例嘅 z 檢驗）：
所有模型答嘅係同一批題，對錯係配對嘅，配對可以把題目難度嘅方差消掉。
精確二項檢驗**必須喺對數空間算**——`sum(comb(n,i)) * 0.5**n` 喺 n 上千時，
組合數係天文數字嘅大整數而 `0.5**n` 已經下溢成 0.0，相乘直接 `OverflowError`。

## 數據重建

合併四個公開來源（作者自建嘅粵語指令集、粵語 CoT、粵語對話、粵中平行語料），
統一 opencc `s2hk` 字形，兩級去重（整條 + 同 instruction），按來源分層切分，
固定 `seed=42`：**71,202 條**（train 68,202 / dev 1,000 / test 2,000）。
確定性驗過：兩台唔同機器重跑，各來源條數、去重數、切分大細逐項一致。

⚠️ **合併語料唔再分發**——四個來源裡面有一個**冇任何授權聲明**、一個係 **AGPL-3.0**，
佔咗 62%。公開嘅係腳本；可以再分發嘅嗰 27,207 條（自有 + CC0）單獨發喺
[`Zeteng/cantonese-llm-data`](https://huggingface.co/datasets/Zeteng/cantonese-llm-data) 嘅
`v2-clean/`。詳見 [`docs/data-licensing.md`](docs/data-licensing.md)。

以下兩項統計值得注意：
- **50,606 條**記錄喺建庫嗰陣被簡繁歸一化過——公開粵語語料嘅簡繁混排問題係大面積嘅；
- 粵語純度中位數 1.0、均值 0.824。**純度只度量、唔過濾**：清洗閾值最容易將最應該研究嘅樣本丟咗，
  要做消融就用 `--min-yue-ratio`。
