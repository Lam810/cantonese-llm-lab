# 提示词消融：我们的第 4 名是不是提示词选出来的？

> 2026-09-17。8 个模型 × 全量 HKMMLU 26,368 题 × 多个提示词臂，逐题配对。
> 脚本 `eval/prompt_ablation.py`、`eval/prompt_grid.py`，作业
> `deploy/npu_prompt_ablation.sbatch`、`deploy/npu_prompt_grid.sbatch`。

## 为什么要做

早先那张把本项目排第一的 HKMMLU 表报 **0.6227**；按官方严格零样本口径全量重跑
只有 **0.5394**，掉到第 4。差 8.33pp，必须交代清楚这 8.33pp 是什么。

而且有一个更要紧的问题：**第 4 名是不是我换了提示词才掉下来的？**
如果换个提示词我们就能回到第一，那「第 4」这个结论本身就不可靠。

## 提示词的两个因素

旧提示词（`eval_yue.py:241-243`）和新的严格提示词差**三处**，不只是末尾那句：

```
旧（legacy）                          新（strict）
以下係一道香港知識選擇題，請答 A、B、C 或 D。   以下是一道單項選擇題，請直接回答選項字母。
                                       ⟵ 整段係書面粵語 vs 標準書面中文
題目：{q}                              {q}
A. …  D. …                            A. …  D. …
請喺最後一行寫「答案：X」。              答案：
  ⟵ 格式腳手架
```

拆成两个因素做 2×2：

|  | 标准书面中文主体 | 粤语主体 |
|---|---|---|
| **无脚手架** | `strict`（主表） | `yue_strict` |
| **有脚手架** | `scaffold` | `legacy`（= 旧表用的那个） |

**为什么粤语提示词必须单独量**：给粤语专化的模型喂粤语提示词，**可能是真实增益，
不是作弊**。如果它对所有模型都有帮助，那它是个中立的提示词选择；如果只帮我们，
那它和格式脚手架一样，是把自己的短板藏起来。不做满 2×2 就分不清这两种情况。

### ⚠️ 一个我在数据只有 5 个模型时说错的结论

当时（只有 ours / 消融A / chat_7b / llama3 / qwen2 四个对手里的三个跑完）我写的是
**「那句脚手架只帮我们，三个对手全被它拖低」**。补齐 8 个模型之后这句话是错的：

**基座 +5.51pp 和 Thinking 版 +3.98pp 受益都比我们大。** 脚手架帮的是所有
「不会自然只吐一个字母」的模型，拖低的是三个本来就 0 解析失败的对手。
**我们受益排第 3，不是第 1。**

教训很直接：**在一个 8 行的表上，看 5 行就下「只有 X 才如何」这种全称结论，
会把「样本里恰好如此」讲成「本来如此」。** 缺的那 3 行正好是行为最极端的三个
（思维链模型 + 基座），而它们才是最需要格式提示的。

### 仍然成立、而且更精确的那条

**我们的增量里 32% 来自「strict 下连字母都解析不出来」的题，是 8 个模型里占比最高的**
（基座 4%、Thinking 12%、CV-Merged 10%、消融A 0%）。别人涨分主要靠「有空间先推理」，
**我们涨分有三分之一只是「终于能被解析出来了」**。这仍然指向格式服从，而且比原来
那个说法更具体。

配套的一个数字：`scaffold` 下我们的未解析率从 **4.42% 掉到 0.62%**，而
`Qwen2-Cantonese-7B` 反而从 0 升到 **2.36%**——同一句提示词，对不同模型是反方向的。

## 结果二：排名对提示词稳不稳（这才是最要紧的一条）

```
strict   排序:  chat_7b 0.5897 > qwen2 0.5883 > 消融A 0.5560 > ours 0.5394
scaffold 排序:  chat_7b 0.5883 > qwen2 0.5791 > 消融A 0.5747 > ours 0.5695
```

**前 4 名的相对次序在两种提示词下完全一致。**

换句话说：**我们的第 4 名不是提示词选择的产物。** 加上格式脚手架我们涨 3.00pp，
但对手也在动，次序没变。这比「脚手架值多少分」重要得多——它说明主表那个结论
对提示词的选择是稳健的。

（后 4 名有变动：`base_qwen3_8b` 从第 6 升到第 5、`cvmerged` 和 `thinking` 换位。
那几个模型在 strict 下是被格式打废的，不是能力排序。）

## 结果三：旧那个 0.6227 由什么构成

| 成分 | 值 | 怎么测的 |
|---|---|---|
| 官方严格口径全量 | **0.5394** | 主表基准 |
| ＋ 格式脚手架 | +3.00pp | 全量配对，唯一变量是末尾那句 |
| ＋ 「每科前 10 题」子集偏差 | +0.91pp | 把全量结果截成前 10 题重算 |
| ＋ 粤语提示词主体 | 见 2×2 | `yue_strict` / `legacy` 臂 |
| ＋ 旧 harness（HF transformers 生成路径） | 未隔离 | — |
| 旧表报的 | **0.6227** | `eval_yue.py --hkmmlu-gen`，n=660 |

**加了脚手架我们也只有 0.5695，仍低于 `chat_7b` 的 0.5883。** 所以旧那个 0.6227
在当前 harness 下**复现不出来**，它是被撤回、而不是被解释掉的。

2×2 的粤语提示词臂跑完后会把剩下的部分补上；即使全部算清，结论也不变：
**旧数字不作为战绩使用，主表以 `strict` 全量为准。**

## 方法上的两条纪律

**一、提示词是实验条件，不是实现细节。** 我给旧提示词加那句「請喺最後一行寫
「答案：X」」，当时是为了让答案解析得出来——一个纯粹工程性的动机。但它同时
改变了模型的行为空间（允许先推理），也就成了一个实验变量。**任何为了「让脚本跑通」
而加的东西，都要回头检查它有没有变成实验条件。**

**二、对自己有利的口径要当成需要证伪的假设。** 我早先把 scaffold 那一轮叫做
「口径 B」并和 `strict` 并列公布，每个模型取自己最优。听起来公平，实际上：
我加的那句话对我们的加成最大（当时看到的 5 个模型里），而「取各自最优」
把这个不对称性洗掉了。**判断一个口径能不能用，要看它对所有被比较对象是否同等中立，
不是看它听起来公平。**
