# 提示词消融：我们的第 4 名是不是提示词选出来的？

> 2026-09-17。8 个模型 × 全量 HKMMLU 26,368 题 × 多个提示词臂，逐题配对。
> 分析脚本 `eval/prompt_ablation.py`、`eval/prompt_grid.py`。

## 为什么要做

早先那张把本项目排第一的 HKMMLU 表报 **0.6227**；按官方严格零样本口径全量重跑
只有 **0.5394**，掉到第 4。差 8.33pp，必须交代清楚这 8.33pp 是什么。

而且有一个更要紧的问题：**第 4 名是不是我换了提示词才掉下来的？**
如果换个提示词我们就能回到第一，那「第 4」这个结论本身就不可靠。

**先说结论：**

1. **排名是稳的。** 4 种提示词 × 2 种题量 = 8 种组合，`CantoneseLLMChat-v1.0-7B`
   **全部赢我们**。四个臂里它都是第 1、`Qwen2-Cantonese-7B` 都是第 2，我们第 3 或第 4。
   就算允许每个模型各取自己最好的那一臂，也是 0.6018 > 0.5889 > 我们 0.5767。
2. **格式脚手架不是「只帮我们」**（我曾经这么写过，错了）——基座 +5.51pp、
   Thinking +3.98pp 都比我们 +3.00pp 多。但**我们涨的分里 32% 只是「终于能被解析出来」，
   这个比例是 8 个模型里最高的**。
3. **粤语提示词不是自利选择**：5 个粤语专化模型全为正、3 个非粤语原生的全为负，
   是类别效应。我早先担心它是作弊，实测之后这个担心是多余的。
4. **旧那个 0.6227 复现不出来**：完整复刻旧条件（旧提示词 + 每科前 10 题）只测到
   **0.5818**，差 4.09pp ≈ 2.1 个标准误。它是被**撤回**的，不是被解释掉的。
5. **两个因素有显著交互**，所以 8.33pp 不能拆成加法。

## 提示词的两个因素

旧提示词（`eval_yue.py:241-243`）和新的严格提示词差**三处**，不只是末尾那句：

```
旧（legacy）                          新（strict）
以下係一道香港知識選擇題，請答 A、B、C 或 D。   以下是一道單項選擇題，請直接回答選項字母。
                                       ⟵ 整段係書面粵語 vs 標準書面中文
題目：{q}                              {q}
A. …  D. …                            A. …  D. …
請喺最後一行寫「答案：X」。              答案：
  ⟵ 格式腳手架
```

拆成两个因素做 2×2：

|  | 标准书面中文主体 | 粤语主体 |
|---|---|---|
| **无脚手架** | `strict`（主表） | `yue_strict` |
| **有脚手架** | `scaffold` | `legacy`（= 旧表用的那个） |

**为什么粤语提示词必须单独量**：给粤语专化的模型喂粤语提示词，**可能是真实增益，
不是作弊**。如果它对所有模型都有帮助，那它是个中立的提示词选择；如果只帮我们，
那它和格式脚手架一样，是把自己的短板藏起来。不做满 2×2 就分不清这两种情况。

### ⚠️ 一个我在数据只有 5 个模型时说错的结论

当时（只有 ours / 消融A / chat_7b / llama3 / qwen2 四个对手里的三个跑完）我写的是
**「那句脚手架只帮我们，三个对手全被它拖低」**。补齐 8 个模型之后这句话是错的：

**基座 +5.51pp 和 Thinking 版 +3.98pp 受益都比我们大。** 脚手架帮的是所有
「不会自然只吐一个字母」的模型，拖低的是三个本来就 0 解析失败的对手。
**我们受益排第 3，不是第 1。**

教训很直接：**在一个 8 行的表上，看 5 行就下「只有 X 才如何」这种全称结论，
会把「样本里恰好如此」讲成「本来如此」。** 缺的那 3 行正好是行为最极端的三个
（思维链模型 + 基座），而它们才是最需要格式提示的。

### 仍然成立、而且更精确的那条

**我们的增量里 32% 来自「strict 下连字母都解析不出来」的题，是 8 个模型里占比最高的**
（基座 4%、Thinking 12%、CV-Merged 10%、消融A 0%）。别人涨分主要靠「有空间先推理」，
**我们涨分有三分之一只是「终于能被解析出来了」**。这仍然指向格式服从，而且比原来
那个说法更具体。

配套的一个数字：`scaffold` 下我们的未解析率从 **4.42% 掉到 0.62%**，而
`Qwen2-Cantonese-7B` 反而从 0 升到 **2.36%**——同一句提示词，对不同模型是反方向的。

### 排名对提示词是不是稳的？是。而且没有任何缝隙。

**四个臂里，`CantoneseLLMChat-v1.0-7B` 都是第 1、`Qwen2-Cantonese-7B` 都是第 2，
我们都是第 3 或第 4——从没进过前 2。**

而且**就算允许每个模型各取自己最好的那一臂**（这个口径本身不严谨，但它是对我们
最宽松的读法）：

```
chat_7b 0.6018  >  qwen2 0.5889  >  ours 0.5767  >  消融A 0.5756  >  llama3 0.5339
```

**怎么挑都挑不到第一。** 第 3／第 4 那两位在 `legacy` 臂下互换（本项目 0.5767 vs
消融A 0.5756，差 0.11pp，噪声），但这不影响结论。

## 结果三：语言主效应——粤语提示词不是自利选择

`(yue_strict − strict)` 和 `(legacy − scaffold)` 的平均：

| 模型 | 语言主效应 | 语言@无脚手架 | 语言@有脚手架 | 是否粤语专化 |
|---|---|---|---|---|
| **本项目 v2** | **+0.99pp** | +1.26pp (p=7.0e-08) | +0.72pp (p=8.4e-04) | ✅ |
| `Llama-3-Cantonese-8B-Instruct` | **+0.97pp** | +0.99pp (p=1.6e-06) | +0.94pp (p=1.9e-05) | ✅ |
| **本项目 消融A** | +0.65pp | +1.22pp (p=4.0e-11) | +0.09pp (p=0.64) | ✅ |
| `CantoneseLLMChat-v1.0-7B` | +0.65pp | −0.05pp (p=0.78) | +1.35pp (p=4.1e-11) | ✅ |
| `Qwen2-Cantonese-7B-Instruct` | +0.41pp | +0.05pp (p=0.79) | +0.77pp (p=2.7e-04) | ✅ |
| `Qwen3-8B`（基座） | **−0.86pp** | +0.15pp (p=0.65) | −1.86pp (p=2.7e-09) | ❌ |
| `v2.0-8B-Thinking-CV-Merged` | **−1.64pp** | −0.67pp (p=0.041) | −2.61pp (p=8.9e-16) | ❌ |
| `CantoneseLLM-v2.0-8B-Thinking` | **−3.46pp** | −4.79pp (p=2.8e-41) | −2.12pp (p=4.6e-10) | ❌（思维链） |

**5 个粤语专化模型全为正（+0.41 ~ +0.99pp），3 个非粤语原生的全为负。**
这是个**类别效应**，不是「只帮我们」：我们受益最大，但只比 `Llama-3-Cantonese`
的 +0.97pp 高 0.02pp。

**所以「用粤语提示词评粤语模型」本来就不算作弊**——它对整个粤语模型类别都成立，
而且它也不会把我们送上第一（`legacy` 臂我们 0.5767，`chat_7b` 0.6018）。
早先我担心这是自利选择，实测之后这个担心是多余的。**先别假定对自己有利的选择
就是作弊，量一下。**

### 交互项不小，所以 8.33pp 不能拆成加法

| 模型 | 交互（语言×脚手架） |
|---|---|
| `CantoneseLLM-v2.0-8B-Thinking` | **+2.67pp** |
| `CantoneseLLMChat-v1.0-7B` | **+1.40pp** |
| `Qwen2-Cantonese-7B-Instruct` | +0.71pp |
| `Llama-3-Cantonese-8B-Instruct` | −0.04pp |
| **本项目 v2** | −0.54pp |
| **本项目 消融A** | −1.13pp |
| `v2.0-8B-Thinking-CV-Merged` | −1.94pp |
| `Qwen3-8B`（基座） | **−2.01pp** |

两个因素**不可加**：同一个因素在另一个因素的两种取值下效应不同，甚至变号
（`chat_7b` 的语言效应在无脚手架时是 −0.05pp、有脚手架时是 +1.35pp）。
**所以不能把 8.33pp 拆成「脚手架 3.00 + 语言 0.99 + 子集 0.91 + 残差」这样相加**——
这也是为什么必须做满 2×2 而不是分别单独测两个因素。

## 结果四：旧那个 0.6227 到底是什么

`legacy` 臂就是旧提示词本身。把它再截成旧那次一样的「每科前 10 题」（n=660），
就是**对旧测量条件的完整复刻**：

| 模型 | legacy 全量 | **legacy 前10（复刻旧条件）** | strict 前10 |
|---|---|---|---|
| `CantoneseLLMChat-v1.0-7B` | 0.6018 | **0.6076** | 0.6182 |
| **本项目 v2** | 0.5767 | **0.5818** | 0.5485 |
| **本项目 消融A** | 0.5756 | 0.5879 | 0.5636 |
| `Qwen2-Cantonese-7B-Instruct` | 0.5867 | 0.5500 | 0.5652 |
| `Qwen3-8B`（基座） | 0.5062 | 0.5045 | 0.4561 |
| `Llama-3-Cantonese-8B-Instruct` | 0.5270 | 0.4970 | 0.5076 |
| `CantoneseLLM-v2.0-8B-Thinking` | 0.4179 | 0.3773 | 0.3667 |
| `v2.0-8B-Thinking-CV-Merged` | 0.3757 | 0.3742 | 0.3864 |

**旧表报 0.6227，完整复刻旧条件我只测到 0.5818。** 差 **4.09pp**，而 n=660 的
标准误是 1.91pp（95%CI 半宽 3.74pp）——**4.09pp 刚好落在置信区间外面，约 2.1 个标准误**。

也就是说：**换回旧提示词、换回旧题量，旧那个数字仍然复现不出来。** 剩下的差异
只能归给旧 harness 那条生成路径（`eval_yue.py` 用 HF transformers `model.generate`，
新的用 vLLM）。**最可能的具体原因**是 chat template 的应用方式不同——旧的「开思维链」
分支不追加那个强制闭合的 `<think>\n\n</think>` 后缀，提示词字符串本身就不一样。
**这一项我没有单独隔离**，所以只能说是最可能的候选，不能当已证实的解释。

**但排名这件事没有任何缝隙：**

```
legacy 前10:  chat_7b 0.6076  >  ours 0.5818
strict 前10:  chat_7b 0.6182  >  ours 0.5485
四臂全量:     chat_7b 第 1，qwen2 第 2，我们第 3 或第 4
各取最优臂:   chat_7b 0.6018 > qwen2 0.5889 > ours 0.5767
```

**4 种提示词 × 2 种题量 = 8 种组合，`CantoneseLLMChat-v1.0-7B` 全部赢我们。**
所以 0.6227 **是被撤回的，而不是被解释掉的**；主表以 `strict` 全量为准。

## 结果五：解析失败率四臂对照——是脚手架在修它，不是语言

|---|---|---|---|---|
| `CantoneseLLM-v2.0-8B-Thinking` | 0.0825 | 0.1175 | 0.1346 | 0.1383 |
| `v2.0-8B-Thinking-CV-Merged` | 0.0736 | 0.0786 | 0.1079 | 0.1176 |
| **本项目 v2** | **0.0442** | **0.0062** | 0.0401 | 0.0096 |
| `Qwen3-8B`（基座） | 0.0281 | 0.0302 | 0.0423 | 0.0456 |
| `Llama-3-Cantonese-8B-Instruct` | 0.0005 | 0.0128 | 0.0095 | 0.0190 |
| **本项目 消融A** | 0.0000 | 0.0013 | 0.0015 | 0.0073 |
| `Qwen2-Cantonese-7B-Instruct` | 0.0000 | 0.0236 | 0.0011 | 0.0089 |
| `CantoneseLLMChat-v1.0-7B` | 0.0000 | 0.0002 | 0.0000 | 0.0004 |

我们的解析失败率：加脚手架 **4.42% → 0.62%**（降 86%），换粤语提示词
4.42% → 4.01%（几乎不动）。**修好格式的是那句脚手架，不是语言。**
这和「我们的短板是格式服从」完全一致——短板的位置，被能修它的那个干预指出来了。

反过来两个思维链模型的解析失败率在四个臂里**越改越高**（0.0825 → 0.1383），
说明它们的问题不是缺一句提示，是根本不受控。

## 方法上的两条纪律

**一、提示词是实验条件，不是实现细节。** 我给旧提示词加那句「請喺最後一行寫
「答案：X」」，当时是为了让答案解析得出来——一个纯粹工程性的动机。但它同时
改变了模型的行为空间（允许先推理），也就成了一个实验变量。**任何为了「让脚本跑通」
而加的东西，都要回头检查它有没有变成实验条件。**

**二、对自己有利的口径要当成需要证伪的假设。** 我早先把 scaffold 那一轮叫做
「口径 B」并和 `strict` 并列公布，每个模型取自己最优。听起来公平，实际上：
我加的那句话对我们的加成最大（当时看到的 5 个模型里），而「取各自最优」
把这个不对称性洗掉了。**判断一个口径能不能用，要看它对所有被比较对象是否同等中立，
不是看它听起来公平。**
