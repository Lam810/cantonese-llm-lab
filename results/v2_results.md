# v2 结果：Qwen3-8B + LoRA

配方针对 v1 的四个缺陷逐条修：**加验证集 + 早停**、LoRA 从只挂 q/v 的 r=8 扩到挂满七个线性层的 r=32、
fp32 全精度训练改成 bf16 基座 + fp32 适配器、loss 只算 assistant 段。全程**不量化**。

## 训练

| | |
|---|---|
| 基座 | `Qwen/Qwen3-8B`，bf16 |
| LoRA | r=32 / alpha=64 / dropout 0.05，挂 q,k,v,o,gate,up,down；可训练 87.3M / 8.28B = **1.055%** |
| 精度 | 基座 bf16，LoRA 参数 fp32（peft 0.20 默认就是 fp32，**实测确认**而非假设） |
| 数据 | train 68,202 / dev 1,000，`max_len` 1024 |
| 优化 | lr 1e-4 cosine，warmup 3%，wd 0.01，有效批 16（4×H100 × bs4 × accum1） |
| 把关 | `eval_strategy=steps`（每 400 步）+ 早停 patience=3 + `load_best_model_at_end` |
| 用时 | **1 小时 1 分**，8,526 步跑满 2 epoch（未触发早停，说明还在改善） |

## 评测

对照组是它自己的基座 `Qwen3-8B`，**基座是唯一变量**。
HKMMLU 取 66 个 config 各 50 题（n=3300，标准误约 0.85pp）；生成类 30 条日常粤语提问，贪心解码。

| | HKMMLU | HK 子集 | HKDSE | 書面粵語純度 | 退化率 | 中位長度 | PPL 留出 | **PPL 粵語維基** | bpc 維基 |
|---|---|---|---|---|---|---|---|---|---|
| **v2 (8B)** | **0.6094** | 0.5957 | **0.6000** | **0.9591** | **0.000** | 109 | **9.97** | **13.57** | **2.93** |
| `Qwen3-8B` | 0.5700 | 0.5791 | 0.5400 | 0.0924 | 0.000 | 194 | 26.72 | 21.69 | 3.45 |

三句话总结：

1. **粤语语域是质变**：0.0924 → 0.9591。原版基本不写粤语，用普通话回答粤语提问。
2. **分布外泛化是真的**：粤语维基（训练里完全没用过）困惑度 21.69 → 13.57、
   bits-per-char 3.45 → 2.93。不是背训练集。
3. **知识增益温和**：HKMMLU +3.94pp、HKDSE +6.0pp，约 4.6σ，统计上真实但幅度不大。
   只喂问答数据的 LoRA 本来就不该带来大幅知识提升。

## ⚠️ 口径更正（2026-09-16）：上表两个数字偏乐观

上表是 2026-09-14 的口径，**没有错，但两处自我设限让数字偏乐观**。用更严的口径重测后：

| | 旧口径 | 新口径 | 差 |
|---|---|---|---|
| HKMMLU v2 | 0.6094（每 config 抽 50，n=3300） | **0.6019**（全量 n=26,368） | −0.75pp |
| HKMMLU 基座 | 0.5700 | **0.5789** | +0.89pp |
| **HKMMLU 增益** | **+3.94pp** | **+2.29pp**（macro +2.76pp） | **−1.65pp** |
| 书面粤语纯度 | 0.9591（30 条提问） | **0.8975**（117 条提问） | −6.16pp |

**为什么变了：**

1. **HKMMLU 从抽样改全量。** 数据集实际有 26,368 题（早先我按 `wc -l` 报成 27,811，那是被 CSV 里带换行的引号字段虚增的；用 csv 解析器数是 26,368，逐题计分 0 丢弃），之前每个 config 只抽 50 题
   （n=3300）。抽样是**均衡**的（每类等量），全量是**不均衡**的（config 从 99 题到
   2204 题）。两个口径都合法，但均衡抽样把增益高估了 1.65pp。全量的标准误从 0.85pp
   降到 0.29pp，而且不再有抽样选择问题，所以现在以全量为准。
   **macro 平均**（各 config 准确率的算术平均，消除长度不均）是 v2 0.6075 / 基座 0.5799，
   增益 +2.76pp——三个口径都指向「真实增益在 2~3pp」。
2. **纯度提问从 30 条扩到 117 条。** 原来那 30 条全是日常／香港本地话题，模型最擅长；
   扩充的 87 条里有知识解释类（「点解天空系蓝色嘅？」），模型更容易滑回普通话。

**一个很强的复现性证据：** v2 在**前 30 条子集**上重测出来是 **0.9591**——与旧口径
**逐位一致**。不同时间、不同作业、改过的脚本，子集完全复现。
所以不是脚本变了，是**原来的提问集偏容易**。

增益本身极显著（配对检验 p=1.3e-14），只是幅度比原先报的小。
和其他粤语模型的横向对照见 [`sota_comparison.md`](sota_comparison.md)。
只用公开数据训练的消融见 [`ablation_clean_data.md`](ablation_clean_data.md)
——**结果是它反而更好**。

## ⚠️ 一个被我自己修掉的错误结论

第一版评测给出的是 **HKMMLU +31.85pp**（v2 0.6073 vs 基座 0.2888）。**那个数字是错的。**

选择题打分法是「比较第一个位置上 A/B/C/D 四个字母 token 的 logprob」，而 **Qwen3 默认开思维链，
基座的第一个 token 是 `<think>`** —— 量到的是「它想先想一想」，不是它的知识。
基座因此只有 0.2888（接近随机 0.25）；`enable_thinking=False` 之后是 **0.5700**。
v2 因为训在直答数据上，第一个 token 本来就是字母，所以不受影响。

**所以那 +31.85pp 里的绝大部分是输出格式差异，不是知识差异。**
修正后是 +3.94pp（抽样口径），换成全量口径后是 **+2.29pp**（见上一节）。

同一个坑在生成类任务上也有：不关思维链，基座满屏普通话推理，「粤语纯度」量的是它的思考过程
而不是它的回答（0.0096 vs 关掉后的 0.0924）；而 **v2 的退化率在开思维链时是 6.7%、关掉后是 0.0%**。

`eval_yue.py` 现在有 `--hkmmlu-think` / `--purity-no-think` 两个开关，选择题默认关思维链。

**教训：对带思维链的模型做「第一个 token」类打分，必须先确认第一个 token 是不是答案位。**
这和 v1 那次事故是同一类错误（拿一个没验证的数字当结论），区别只是这次在发布前抓到了。
