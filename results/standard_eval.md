# 标准评测：官方口径下我们到底在什么水平

> 2026-09-17。8 个模型 × 3 个任务，HKMMLU 全量 26,368 题、官方翻译任务各 2,000 条、
> 书面粤语纯度 117 条提问。全部在同一套脚本、同一批硬件（昇腾 910C）、同一组
> 采样参数（贪心）下跑出来，逐题配对检验。脚本在 `eval/`，作业脚本在 `deploy/`。

## 先说结论，包括要撤回的那一条

**HKMMLU 我们排第 4，不是第一。** `results/sota_comparison.md` 早先那句
「HKMMLU 第一 + 纯度第一 + 输出最短」在官方口径下**不成立**，见文末〈撤回与更正〉。

在官方口径下，三个任务的排名是：

| 任务 | 我们的位置 | 第一名 |
|---|---|---|
| HKMMLU 选择题（知识） | **第 4 / 8** | `CantoneseLLMChat-v1.0-7B` 0.5897 |
| 书面粤语纯度（产出语域） | **第 2 / 8** | `CantoneseLLM-v2.0-8B-Thinking` 0.9655 |
| 官方翻译 普→粤（产出粤语） | **第 1 / 8** | 本项目 51.57 |
| 官方翻译 粤→普（理解粤语） | **第 4 / 8** | `CantoneseLLMChat-v1.0-7B` 59.51 |
| 输出 token 数（非思维链部署） | **同级最低档** | 见下 |

一句话概括能力的形状：**我们的模型学会了粤语的「输出语域」，没学会「语域之间的
转换」，而且指令服从度是短板。** 这和训练数据的性质完全对得上——我们喂的是粤语
问答，不是翻译对，也不是格式服从数据。

## 口径

**HKMMLU 官方标准是 zero-shot prompting**（数据集 README：*"Model performance on
multi-choice tasks in HKMMLU using zero-shot prompting"*，
[arXiv:2505.02177](https://arxiv.org/abs/2505.02177)，
[榜单](https://huggingface.co/spaces/zhenghaozhu/llm-hkmmlu-leaderboard)）。

提示词（严格零样本，`eval/eval_hkmmlu_official.py` 里的 `MC_PROMPTS["strict"]`）：

```
以下是一道單項選擇題，請直接回答選項字母。

{題目}
A. {選項}
B. {選項}
C. {選項}
D. {選項}

答案：
```

- 贪心解码（`temperature=0`），可复算
- 解析：先找「答案/answer/選/选 + 字母」，再退回裸字母。**不能用 `\b`**——中文字在
  Unicode 下算 `\w`，「答案是A。」里 A 左边没有词边界，所以用
  `(?<![A-Za-z])([ABCD])(?![A-Za-z])`
- 解析不出来的**单独记 `unparsed_rate`，按答错计，不静默丢弃**
- 思维链模型先 `strip_think()` 再解析，`max_tokens=512` 留够，免得在 think 块中间截断

### 三件要如实标注的

**1. 我们的解析失败率 4.42%，是能正常工作的模型里最高的。** 两个强对手是
**0.0000**。这不是知识问题，是「只输出一个字母」这条指令没服从，白丢分——
按答错计，4.42% 直接从分数里扣掉。

这是我们的弱项。反过来 `hkdse_*`（香港中学文凭考试，9 科）0.5351 **是第一**，

**3. 消融 A（只用公开数据训的那版）反而比完整版高 1.65pp**（p=5.8e-10）。
这和 `results/ablation_clean_data.md` 的结论一致，不是偶然。

| 3 | **本项目 消融A（仅公开数据）** | 0.8706 | 0.8536 | 0.0085 | 61 | 67 |

**纯度我们是第 2，不是第 1。** 同基座的 Thinking 版 0.9655 比我们高 8.6pp，
它写的粤语确实比我们纯。这一条早先也写错了，见〈撤回与更正〉。

**但「纯度高」在这个模型身上不等于「可用」**：它 HKMMLU 0.3993（倒数第二）、

### 前 30 条 vs 全 117 条：把提问集扩大，对手掉得比我们多

| 模型 | 前30 → 全117 |
|---|---|
| `CantoneseLLMChat-v1.0-7B` | 0.7540 → 0.5376（**−21.6pp**）|
| `Llama-3-Cantonese-8B-Instruct` | 0.8007 → 0.4890（**−31.2pp**）|
| `Qwen2-Cantonese-7B-Instruct` | 0.8547 → 0.8225（−3.2pp）|
| **本项目 v2** | 0.8612 → 0.8791（**+1.8pp**）|

原来那 30 条提问对几个对手偏易。**扩到 117 条之后我们相对对手的优势是变大的**，
所以这次扩集不是对我们有利的挑选——恰恰相反。前 30 条保留原样、不改措辞，
就是为了让新旧数字可比。

### 纯度这个指标有一个已知偏差，方向对我们不利

低虚词密度的输出更容易拿满分。同一条提问：

| 模型 | 粤语虚词 | 普通话虚词 | ratio |
|---|---|---|---|
| 本项目 | **17** | 1 | 0.944 |
| `v2.0-8B-Thinking` | 10 | 0 | **1.000** |
| `CantoneseLLMChat-v1.0-7B` | 8 | 0 | **1.000** |

对手因为分母小拿到 1.000，我们因为一个「的」扣到 0.944，而我们的粤语虚词
**绝对密度最高**。这一条记在这里，没有为了凑结果去改指标。

### ⚠️ 粤→普 这一列有一个尚未剥离的混淆：繁简

官方 can2man 的参考译文是**简体**，我们的模型输出**繁体**。chrF 是字符级指标，
繁简不同会让语域已经转对的句子拿到接近 0 的分。实测样例：

```
src 鐳射影碟喺香港同澳門地區仍然係一種常見嘅稱呼。
ref 镭射影碟在香港和澳门地区仍然是一种常见的称呼。
hyp 鐳射影碟在香港和澳門地區仍然是一種常見的稱呼。
```

喺→在、同→和、係→是、嘅→的 **全部转对了**，只差字形。

所以上表 23.92 这个数里混了两件事：**没转换语域** 和 **没按要求输出简体**。
提示词明写了「簡體中文」，输出繁体确实是没照做、该罚；但把它算成
「不会理解粤语」是错的。已加 `chrF_t2s`（两边都归一到简体再算，只量语域转换）
并重跑，结果补在本节 —— **在拿到那组数字之前，不要引用 23.92 去论证理解能力。**

也有真实的理解失败，不全是字形。同一批样例里：

```
src 我個健身Plan玩完，因為我整親。
ref 我的健身计划完蛋了，因为我受伤了。
hyp 我的健身計劃已經完成，因為我親自制定的。      ← 「玩完」「整親」两个词都理解反了
```

## 撤回与更正

### 1. 撤回「HKMMLU 第一」

`results/sota_comparison.md` 里那张把我们排第一的 HKMMLU 表用的是
**logprob 口径**（比较 A/B/C/D 四个字母 token 的首 token logprob）。该口径绕开了
指令遵循这个混淆变量，**但和官方榜单不可直接比**，当时文档里也写了这一点。
现在按官方生成口径全量重跑，我们从第 1 掉到第 4。**以官方口径为准。**

### 2. 撤回「纯度第一」

同一份文档写「纯度第一」，依据是 logprob 口径下 `v2.0-8B-Thinking` 的纯度
0.8088。那个数字是在「强行关思维链」的兜底模板下测的，而那个模板对它无效。
在官方口径下它是 **0.9655**，比我们高。**我们是第 2。**

### 3. 早先那张生成式的表（口径 B）用了一句额外的提示词，不该当成「另一种口径」

`results/sota_comparison.md` 的「口径 B」把我们排第一（0.6227）。那一轮的提示词
末尾多一句 **「請喺最後一行寫「答案：X」」**（`eval/eval_yue.py:243`）。这句话同时
做了两件事：给解析器一个锚点，以及允许模型先写推理再作答（中位输出 51 tok，
官方口径下只有 13 tok）。

它对我们值 **+8.3pp**，对最强对手只值 **+1.5pp**——因为对手本来就 0 解析失败、
不需要脚手架。**把它当成「另一种口径」报出去，等于用我自己加的提示把我们自己的
指令遵循短板盖住。**

已排除的替代解释：口径 B 只跑了每科 10 题（n=660）。把官方口径的全量结果截成
同样的「每科前 10 题」，8 个模型的差都在 ±3.3pp 内（SE 1.91pp），**不是子集偏易**。

已把它降级成 `--mc-style scaffold` 这个可开关的消融项（主表固定用 `strict`），
并全量重跑做逐题配对，量清「格式脚手架值多少分、其中多少只是解析失败翻盘」。
结果补在 `results/prompt_ablation.md`。

### 4. 量化闸门的阈值我定错过两次

见 `results/quantization.md` 与 `eval/gate_check.py` 的文档字符串。简述：
先是把 logprob 口径的绝对阈值（0.55）搬到生成口径用；改成相对同口径对照后，
又拿两个独立比例的标准误去判配对差异。现在用非劣效检验，δ=2.0pp。

## 复现

```bash
# 选择题（严格零样本，全量）
python eval/eval_hkmmlu_official.py --model <路径> --name <名字> \
   --task mc --hkmmlu-dir $LAB_ROOT/data/HKMMLU --limit-per-cfg 0 \
   --max-tokens 512 --mc-style strict --out <名字>_mc.json

# 官方翻译任务（两个方向，各 2000 条，存下全部译文）
python eval/eval_hkmmlu_official.py --model <路径> --name <名字> \
   --task trans --trans-dir $LAB_ROOT/data/hkmmlu_translate \
   --max-tokens 256 --save-hyps --out <名字>_trans.json

# 书面粤语纯度
python eval/eval_hkmmlu_official.py --model <路径> --name <名字> \
   --task purity --purity-max-new 128 --out <名字>_purity.json

# 汇总与配对检验
python eval/summarize_std.py   <结果目录>
python eval/summarize_trans.py <结果目录>
python eval/compare_models.py --key mc ours_mc.json <其他>_mc.json ...

# 提示词消融（strict vs scaffold）
python eval/prompt_ablation.py <strict结果目录> <scaffold结果目录>
```

作业脚本：`deploy/npu_std_eval.sbatch`（8 模型 × 3 任务铺在 8 个 die 上）、
`deploy/npu_prompt_ablation.sbatch`、`deploy/npu_trans_rescore.sbatch`、
`deploy/npu_full_gate.sbatch`。
