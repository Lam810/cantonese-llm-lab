# 把 16GB 权重从隔离集群搬到公开托管站：实际可行的做法

训练和评测都在一个**连不上 huggingface.co** 的集群上；能上传 HF 的只有一台开发机，
而它到集群的 tailnet 链路在 **10 KB/s ~ 4.7 MB/s** 之间剧烈抖动、还会整段断开。
这份记录是最后走通的方案和沿途量到的每一段带宽。

## 各段实测带宽

| 路径 | 速度 | 备注 |
|---|---|---|
| 集群内部（跳板机 → NPU 集群） | **236 MB/s** | 同校园网，16.4GB 用 77 秒 |
| 跳板机 → 国内模型托管站 | **10.7 MB/s** | 16.4GB 用 25.6 分钟 |
| 开发机 ← 国内模型托管站 | **1.76 MB/s** | **多连接并行不加速**，是出网上限 |
| 开发机 ← HF | 8.7 MB/s | |
| 开发机 → HF | **0.10–0.37 MB/s** | 同一个代理，**上传方向被限速 20–80 倍** |
| 开发机 ↔ 跳板机（tailnet，Windows 原生 ssh） | 2.7 MB/s → 退化到 10 KB/s | DERP 中继，RTT 1.5s |
| 同上，WSL 原生 ssh | 0.5 MB/s | |
| 同上，sftp | 60 KB/s | 高 RTT 下 sftp 的窗口机制吃亏 |
| 同上，经另一台机器双跳 | **2.5 KB/s** | 叠中继 = 灾难 |

## 最终方案：只搬 adapter，本机合并，再逐字节验证

搬 16.4GB 不现实，但 **LoRA adapter 只有 349MB**，而基座是公开的、从 HF 直下很快。所以：

1. 跳板机把合并产物和 adapter 都上传到国内托管站（10.7 MB/s）
2. 开发机**只下 adapter**（349MB / 1.76 MB/s ≈ 3 分钟）
3. 基座从 HF 直下开发机（17GB / 8.7 MB/s ≈ 33 分钟），本机流式合并
4. **用带鉴权的 HTTP range 请求，把本机合并产物和集群那份逐字节比对**

第 4 步是关键：否则"本地重新合并的权重"和"实际被评测的权重"只是**假定**等价。
抽 3 个张量（含相对差最大的、以及未被 LoRA 改动的 embedding 作对照）各 32,768 个
bf16 元素，**100% 相同**；`merge_check` 也对得上（252/252 张量、最大 `‖ΔW‖/‖W‖` 0.0781 vs 0.0782）。

搬 1/47 的数据量，换来位级等价的产物。

## 五个具体的坑

**① 流式合并必须逐分片，否则内存爆。**
8B 的 base(16GB) + merged(16GB) 同时驻留需要 32GB+；开发机只有 15GB。
按 safetensors 分片逐个处理，峰值约 5GB。见 `train/merge_lora_stream.py`。

**② 高 RTT 链路上 `dd bs=1M skip=N` 优于 sftp，但任意字节偏移要用 `tail -c +N | head -c`。**
`dd bs=1` 会让远端做上百万次单字节读，直接卡死。另外**截断的输出就是该块的合法前缀**
——把它收下并按实得字节推进偏移，进度才单调向前，否则每次超时都整块丢弃、永远 0%。

**③ 代理可能是不对称的。** 同一个代理下载 8.7 MB/s、上传 0.1 MB/s。
搬大文件前**分别测两个方向**，别用下载速度推断上传耗时。

**④ 别写到 Windows 挂载盘。** WSL 写 `/mnt/<drive>` 会叠加 drvfs 与
Windows→WSL interop 两层损耗；同一条链路换成写 Linux 盘快一个数量级。
而且 WSL 的 `truncate` 和 Windows 进程的 `>>` 会在挂载盘上抢同一个文件句柄
（报"另一个程序正在使用此文件"）。

**⑤ `~/.ssh/config` 里重复的 `Host` 块会静默生效。**
ssh 对每个关键字取**最先出现**的值。我有两个 `Host cpu-tail` 块，顶部那个的 `ProxyJump`
一直压着底部的真配置，于是"直连"其实一直在走双跳（2.5 KB/s）。
`ssh -G <host>` 可以打印最终生效的配置，排查这类问题比读文件可靠。

## 一条纯属自找的

`pkill -f <pattern>` / `pgrep -f <pattern>` 时，如果 `<pattern>` 出现在**自己这条命令行里**，
就会杀掉自己的 shell。我在一轮里踩了四次（症状是命令半途中断，还毁过一个正在 `sed -i` 的脚本）。
用 pidfile，或者 `pgrep -f 'hf_[p]ublish'` 这种方括号写法断开自匹配。
